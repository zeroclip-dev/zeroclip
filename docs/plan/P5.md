### P5.6 · Ffmpeg::probe (ffprobe: streams, duration, keyframes), audio_samples, waveform file_key

Size **M** · no hardware needed · depends on P5.5

**Files:**
- `crates/zc-editor/src/ffmpeg.rs`
- `crates/zc-editor/src/waveform.rs`

**Reuse:**
- run() helper (P5.5)
- StreamInfo in crates/zc-editor/src/concat.rs
- Hns::from_secs_f64 in crates/zc-core/src/time.rs (off the hot path, fine)

**Steps**

1. `pub struct ProbeInfo { pub stream: StreamInfo, pub duration: Hns, pub keyframes: Vec<Hns> }`; ffprobe path = `self.exe.with_file_name(if cfg!(windows) {"ffprobe.exe"} else {"ffprobe"})`.
2. `probe(&self, path)`: (a) `ffprobe -v error -show_entries stream=codec_type,codec_name,width,height,avg_frame_rate:format=duration,start_time -of default=noprint_wrappers=1 <path>`; pure `parse_streams(&str) -> Result<(StreamInfo, Hns /*duration*/, Hns /*start_time*/), String>`: lines `key=value` in stream order; the first `codec_type=video` stream gives codec_name (h264/hevc/av1 -> Codec, else Err("unsupported video codec X")), width, height, avg_frame_rate "60/1" -> rounded num/den; count `codec_type=audio`; format duration/start_time -> Hns::from_secs_f64. (b) keyframes: `ffprobe -v error -select_streams v:0 -show_entries packet=pts_time,flags -of csv=print_section=0 <path>` - packet level, demux only, fast even for 5-minute clips; pure `parse_keyframes(&str, start: Hns) -> Vec<Hns>`: keep lines whose flags start with 'K', subtract start_time (ffmpeg's -ss is relative to the file start, raw pts_time is not), sort.
3. `audio_samples(&self, path, sample_rate: u32) -> Result<Vec<f32>, FfmpegError>`: run ffmpeg `-i <path> -map 0:a:0 -ac 1 -ar <rate> -f f32le -` and convert stdout with `chunks_exact(4).map(|b| f32::from_le_bytes([b[0], b[1], b[2], b[3]]))`. Clips without audio fail; callers treat Err as "no waveform".
4. waveform.rs `pub fn file_key(path: &Path) -> io::Result<String>`: FNV-1a 64 over (len as LE bytes, first 64 KiB, last 64 KiB) -> `format!("{len:x}-{hash:016x}")`. Comment: std's DefaultHasher isn't stable across Rust releases; reading 128 KiB beats hashing a 750 MB file; ponytail: same size+head+tail collide, acceptable for a cache.
5. Tests on canned ffprobe output for parse_streams/parse_keyframes (incl. a non-zero start_time); file_key: equal files equal keys, a changed last byte changes the key.

**Verify**

cargo test -p zc-editor
cargo clippy --workspace --all-targets -- -D warnings
Manual (ffmpeg installed): probe a recorded clip in a scratch test or via P5.9.

### P5.14 · Track mixer: per-track volume, mute and solo, with a mixed export (D26)

Size **M** · **hardware check: 0xtikaa** · depends on P5.6, P5.9, P5.10

**Files:** `crates/zc-editor/src/mix.rs` (new), `crates/zc-editor/src/ffmpeg.rs`, `src/ui/editor.rs`

**Reuse:** the probe from P5.6 (lists every audio stream with its title), the waveform from P5.10 (one per track), the job helper from P5.8.

**Steps**

1. Pure `MixPlan { tracks: Vec<TrackMix { index, gain_db, mute, solo }> }` with `fn filter_graph(&self) -> Option<String>`. Muted tracks (or non-soloed ones when any track is soloed) are dropped; the rest become `[0:a:N]volume=XdB[aN]`, then `amix=inputs=K:normalize=0[out]`. `None` when no track survives. Unit-test the strings, including solo, mute-all, and a single track.
2. `Ffmpeg::export_mixed(input, range, plan, output)`: video **stream-copied** (`-c:v copy`), the plan's graph through `-filter_complex`, audio re-encoded to AAC (`-c:a aac -b:a 192k`), `-movflags +faststart`. This is the "Share" output: one audio track, so Discord and browsers play it. A second action, "Export all tracks", keeps every original stream and only applies the trim.
3. Editor UI: under the timeline, one row per audio track: its label (from the stream title), a waveform, a volume slider (−60…+12 dB), Mute and Solo toggles. Remember the plan per clip in `zc-store` (`clips` row, JSON), so reopening a clip keeps the mix.
4. Preview: render the mix of the selection into a temp WAV with the same filter graph (no video), then open it with ffplay or the default player next to the video preview. State plainly in the UI that the preview is the audio only.
5. Never touch the source file; the export refuses to overwrite.

**Verify**

Gate green; `cargo test -p zc-editor mix_`. Hardware (0xtikaa): record a clip with Game + Discord + Mic tracks, mute Discord and raise the mic by 6 dB in the editor, export mixed, and play it in a browser: no Discord audio, louder mic, video unchanged and identical to the source (`ffprobe` shows `copy`).
