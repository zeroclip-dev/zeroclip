### P6.10 · YouTube resumable, throttled upload

Size **M** · **hardware check: 0xtikaa** · depends on P6.9, P1.2, P3.7 · blocked by Q9

- zc_mux::pacing::WritePacer::delay (crates/zc-mux/src/pacing.rs, Phase 3) for throttling
- access_token() (P6.9)
- test_server helper (P6.4)

**Steps**

1. Init: POST `https://www.googleapis.com/upload/youtube/v3/videos?uploadType=resumable&part=snippet,status` with bearer token, headers X-Upload-Content-Type: video/mp4 and X-Upload-Content-Length, JSON `{"snippet":{"title":…,"categoryId":"20"},"status":{"privacyStatus":"unlisted","selfDeclaredMadeForKids":false}}` -> 200 + `Location` = session URI. 403 quotaExceeded -> Rejected("YouTube upload quota used up for today").
2. Chunks of 8 MiB (must be a multiple of 256 KiB): read at `offset` (tokio::fs::File + seek, or spawn_blocking), PUT to the session with `Content-Range: bytes {offset}-{end}/{total}`. 308 -> pure `parse_range("bytes=0-262143") -> Some(262144)` gives the next offset (no Range -> 0); 200/201 -> JSON `{id}` -> progress(total) -> `UploadedUrl(format!("https://youtu.be/{id}"))`. 401 -> refresh once and retry the chunk.
3. Resume (DESIGN §10): 5xx or a transport error -> `Backoff::new(Hns::from_secs(1), Hns::from_secs(60))`, sleep `next_delay().to_duration()`, then query status with an empty PUT `Content-Range: bytes */{total}` -> 308 Range -> resume there (200/201 -> done); reset the backoff after each successful chunk; give up after 6 h -> Network (ponytail ceiling). Log `resuming at byte N`.
4. Throttle: YouTube gets `limit_bytes_per_sec: Option<u64>` from settings.upload_limit_kbps; `let pacer = limit.map_or(WritePacer::unlimited(), WritePacer::limited);` after each chunk sleep `pacer.delay(sent_since_start, Hns::from(started.elapsed()))`. Add `zc-mux.workspace = true` to zc-destinations and update the ARCHITECTURE crate table.
5. progress after every chunk.
6. Tests: parse_range; Content-Range formatting; a mock-server two-chunk upload with one 308 in between.

**Verify**
