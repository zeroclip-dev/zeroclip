## Notes for this area

### Pitfalls

Cross-phase blockers:
- The Recorder can't be constructed before Phase 3. `Recorder::new` calls `DvrBuffer::new`, which is `todo!("Phase 3")`, and `Tee::write` is `todo!` too. The engine can't run real audio sources end to end until Phase 3 (or until Phase 1 works around it). That is why P2.20 is a standalone spike with its own `PacketSink`, and why P2.18 has to check what Phase 1 left on `Actor`.
- The Phase 2 done-when can't be checked end to end without a muxer (Phase 3). The spike measures audio PTS against QPC. WGC's `SystemRelativeTime` is QPC-based too, so bounded audio-to-QPC drift means bounded A/V drift. The clap test repeats after Phase 3.

windows-rs 0.62 features and API surprises:
- **`CreateEventW`** is cfg-gated on `Win32_Security`, so zc-audio must add that feature.
- **`RegisterClassExW` / `WNDCLASSEXW`** are gated on `Win32_Graphics_Gdi`, which zc-win doesn't enable. Use the built-in `w!("STATIC")` class for the `HWND_MESSAGE` window (P2.7), or add the feature and handle `ERROR_CLASS_ALREADY_EXISTS` on a second spawn.
- **`CLSID_AACMFTEncoder`** isn't in windows 0.62. Define `{93AF0C51-2275-45D2-A35B-F2BA21CAED00}` locally and check it against wmcodecdsp.h.
- **`HID_USAGE_*`** constants need an extra feature. Use the literals 0x01/0x02/0x06.
- **`WAVE_FORMAT_IEEE_FLOAT`** is in `Win32_Media_Multimedia`. The plan avoids it by capturing PCM16.
- **`PROPVARIANT`:** use the plain `windows::Win32::System::Com::StructuredStorage::PROPVARIANT` for the VT_BLOB activation params. `windows_core::PROPVARIANT` has a Drop that would PropVariantClear a stack blob. The blob's params struct must outlive the async activation wait.
- **`MFT_OUTPUT_DATA_BUFFER`** fields are `ManuallyDrop<Option<..>>`. Drop `pSample` and `pEvents` after every `ProcessOutput`, or COM references leak on the audio thread.
- **Completion handler:** `IActivateAudioInterfaceCompletionHandler` must be agile: `#[implement(IActivateAudioInterfaceCompletionHandler, IAgileObject)]`, with `IAgileObject` from `windows::Win32::System::Com`. The `_Impl` method takes `windows_core::Ref<IActivateAudioInterfaceAsyncOperation>`.
- **QPC units:** WASAPI's `u64QPCPosition` is already in 100 ns units. Don't pass it through `zc_win::clock::ticks_to_hns`. Process loopback may report 0 or set `AUDCLNT_BUFFERFLAGS_TIMESTAMP_ERROR`; fall back to `SampleTimeline::expected()` or `clock::now()`.
- **`Win32_UI_Input_KeyboardAndMouse`** is declared in zc-input but probably unused. Remove it if it is (CONTRIBUTING.md rule 8).
- **`tracing`:** zc-audio has no `tracing` dependency yet. Add it (`tracing.workspace = true`).

Lint traps that turn into CI failures:
- **`expect` in test builds:** `#[expect(dead_code)]` on scaffolding that a `#[cfg(test)]` test uses is unfulfilled in test builds, and `cargo clippy --all-targets -D warnings` then fails. Use `#[cfg_attr(not(test), expect(dead_code, reason = ...))]` (P2.13, P2.14).
- **Scaffold expects to delete as features land:**
  - message_thread.rs:30 `thread_id` (P2.7)
  - aac.rs:17, 23, 34, replaced in P2.13 and removed in P2.15
  - actor.rs:103 `Msg::Health` (P2.18, unless Phase 1 already constructs it)
- **Other workspace lints:** `missing_docs` is warn, so every new pub item needs a doc comment. `undocumented_unsafe_blocks` means every unsafe block needs `// SAFETY:`. `unsafe_op_in_unsafe_fn` is deny. Clippy runs with `-D warnings`.
- **Panics across FFI:** a panic unwinding out of an `extern "system"` callback (WinEvent proc, COM `_Impl` methods) aborts the process. Use `RefCell::try_borrow_mut`, never `unwrap`, and keep callbacks trivial.

Raw Input:
- **Registration conflict with winit:** registration is per process, per usage page and usage, and the last call wins. winit 0.30 registers mouse and keyboard for its own hidden window when the event loop is created (raw_input.rs, called from event_loop.rs:208). zc-input registers later, from the engine started in `ZeroClipApp::new`, so ours wins and winit only loses raw DeviceEvents, which egui doesn't need. If anything ever calls winit `listen_device_events`, the hotkeys silently die. P2.12's manual checks cover this.
- **Mouse traffic:** registering the mouse with `RIDEV_INPUTSINK` means a `WM_INPUT` for every movement (up to 8 kHz). `mouse_buttons` returns an empty Vec (no allocation) for moves, but check CPU in P2.12. If it's measurable, register the mouse only when a binding uses Mouse3-5.
- **Keystroke logging:** the input thread sees every keystroke system-wide, including passwords. The actor currently traces every `Msg` (`tracing::trace!(?msg)`) plus `trace!(%key, down)`, so `ZEROCLIP_LOG=trace` would write keystrokes to the log files. P2.11 must redact this.
- **Stuck keys:** key-ups that happen on the secure desktop (Ctrl+Alt+Del, Win+L, UAC) are never delivered, so the matcher can keep Ctrl or Alt held, and Press bindings that need exact modifiers stop firing until that key is pressed again. Accept this for now; a fix is reset-on-unlock in Phase 4.
- **Elevated games:** UIPI may block raw input to a non-elevated ZeroClip while an elevated game is in front. This is a hardware check.

Audio:
- **AAC bitrates:** the MS AAC encoder accepts only 96, 128, 160 or 192 kbps (`MF_MT_AUDIO_AVG_BYTES_PER_SECOND` of 12000, 16000, 20000 or 24000). The settings UI currently allows 64-320, so snap in the encoder and restrict the UI (P2.22).
- **Compressor channels:** linked stereo needs the channel count, so P2.3 adds a `channels` field (default 2). The specs still compile because they use `..Default::default()`.
- **Endpoint loopback (Windows 10 fallback)** delivers no packets during silence. `SampleTimeline` silence-fills gaps up to 1 s and restarts after longer ones.
- **AAC encoder priming** adds a constant offset of about 21-44 ms. That isn't drift; compensate it with `MasterClock::set_track_offset` once the muxer exists.
- **Settings take effect at different times:** ports are built once at startup, so toggling game audio or mic Off/On needs a restart. PTT ⇄ AlwaysOn is live through `set_gate`. `MicMode::Off` means no mic track at all (the wiring skips `MicSource`), even though the enum doc says "silence".

Docs and phase status:
- CLAUDE.md still says "Current phase: Phase 0". Update it when Phase 2 starts (P2.23).
- Update ROADMAP boxes in the same PR as the code.
- `docs/ARCHITECTURE.md` already lists the audio and message threads; add `SampleTimeline` to its Time section.

### Open questions, as the inventory saw them

Where this disagrees with [README § Decisions](README.md#decisions), the README wins.

Q1, process loopback include vs exclude (the only open question in this area):
- What exists today: D9 already says "include mode, to be verified in Phase 2". zc-audio/game.rs plans PROCESS_LOOPBACK_MODE_INCLUDE_TARGET_PROCESS_TREE. `AudioSource::set_target_process(Option<u32>)` is shaped for include mode. The settings tab has only a "Record the game's audio" checkbox, with no app list.
- Recommendation: include mode. Close Q1 with a new decision entry that references D9 (D9 itself stays unedited). The audio UI should say "capture from the game in focus", not "ignore these apps".
- Why:
  1. windows 0.62's `AUDIOCLIENT_PROCESS_LOOPBACK_PARAMS` holds exactly one `TargetProcessId` and one `ProcessLoopbackMode` per activation. Exclude mode can therefore drop only one process tree per client.
  2. Two exclude clients can't be combined to drop both Discord and Spotify: each capture still contains the other app, and summing them doubles everything else. "Ignore these apps" with several apps can't be expressed at all.
  3. Include mode captures just the game's tree. That already keeps out Discord, music and notifications, which is the reason an exclude list would exist.
  4. The foreground hook (and the Phase 4 profile engine) already supplies the pid.
- Costs to note in the decision:
  1. Audio rendered by a process outside the focused window's tree is missed. UWP games are hosted by ApplicationFrameHost.exe, and some launchers spawn audio in sibling processes.
  2. It needs Windows 11 build 20348+. The P2.17 fallback is whole-system endpoint loopback.
- Who decides: the owner confirms (P2.21 is blocked on Q1). The audio settings UI task P2.22 waits for that.

Decisions that aren't Q-numbered but need 0xtikaa's sign-off:
1. **WASAPI library.** zc-audio/lib.rs leaves "`wasapi` crate vs raw `windows`" as a Phase 2 call. Recommendation: raw windows-rs, recorded as a DECISIONS entry (next free D-number) in P2.14.
   - No second windows-rs version.
   - The audio hot path's no-alloc rule stays under our control; the wasapi crate's helpers read into a VecDeque.
   - Every line stays explainable.
2. **Game-audio target before Phase 4.** actor.rs puts "retarget game audio" under Phase 4, but include mode records nothing without a pid. Recommendation: in Phase 2, follow every foreground change (P2.18), and let Phase 4 restrict it to profiled games. Accepted cost: alt-tabbing to Discord switches the capture target to Discord until you tab back.
3. **Audio clock drift.** This is new design detail. Recommendation: `SampleTimeline` in zc-core (P2.4).
   - Timestamps stay sample-exact, but whenever they disagree with WASAPI's QPC by more than 20 ms they re-align by inserting silence or dropping frames.
   - Without it, a 30-minute recording drifts by 18-180 ms (10-100 ppm), which fails the Phase 2 done-when.
   - Record it in DESIGN §6.
4. **AAC packaging.** Keep raw AAC (`MF_MT_AAC_PAYLOAD_TYPE=0`) as already planned. For fixed 48 kHz stereo AAC-LC, the AudioSpecificConfig is a constant 2 bytes that the Phase 3 muxer can synthesize. ADTS headers exist only in the P2.20 spike so VLC can play its files.

Q8 (multi-monitor and HDR, "Phase 1–2") is video capture, not this area.

**Steps**

1. Add `pub channels: u16` to `CompressorParams` (doc: 'Interleaved channels; all are linked'), with a default of 2 in `impl Default`. The specs only build params with `..Default::default()` or `..p`, so they still compile. Linked stereo needs the channel count: without it, the attack and release times would be off by a factor of the channel count.
2. `output_level_db(input)`: if `input <= threshold_db`, return `input + makeup_db`. Otherwise return `threshold_db + (input - threshold_db) / ratio + makeup_db`.
3. Add fields to `Compressor`: `envelope_db: f32` (current gain reduction, <= 0, starts at 0), `attack: f32` and `release: f32` (one-pole coefficients). Compute them in `new` as `(-1.0 / (ms * 0.001 * sample_rate as f32)).exp()`. Replace the existing 'Phase 2: envelope follower state' comment.
4. `process(samples)`: `for frame in samples.chunks_exact_mut(usize::from(channels.max(1)))`:

   - `target` = 0 if `peak <= 1e-9`; otherwise `level = 20*log10(peak)` and `target = (output_level_db(level) - makeup_db - level).min(0.0)`;
   - `coeff` = `attack` if `target < envelope_db`, else `release`; then `envelope_db = coeff*envelope_db + (1-coeff)*target`;
   - `gain = 10f32.powf((envelope_db + makeup_db)/20.0)`; multiply every sample in the frame by `gain`.
   This allocates nothing and takes no lock. Silence stays exactly 0 even with makeup gain, because 0 * gain = 0.
5. Keep `latency()` returning `Hns::ZERO` (no lookahead).
6. Remove the 4 `#[ignore]` attributes.

### P2.4 · SampleTimeline: keep WASAPI PCM continuous and on the QPC timeline (bounds audio-clock drift)

Size **M** · no hardware needed · depends on nothing

**Files:**
- `crates/zc-core/src/time.rs`
- `docs/DESIGN.md`
- `docs/ARCHITECTURE.md`
- `docs/ROADMAP.md`

**Reuse:**
- zc_core::time::Hns (crates/zc-core/src/time.rs)
- Integer frame-time pattern from SyntheticStream::frame_pts (crates/zc-core/src/testing.rs)

**Steps**

Why: the sound card's sample clock and QPC differ by 10-100 ppm, which is up to 180 ms over 30 minutes. Timestamping AAC frames by sample count alone drifts. Timestamping them with raw per-buffer QPC makes the stream non-contiguous. This pure type does both: sample-exact PTS, re-aligned to QPC whenever the error exceeds a tolerance. It is what makes Phase 2's done-when ('no measurable A/V drift after 30 min') true.
1. In time.rs, under MasterClock, add:
```rust
/// What to do with one captured PCM buffer.
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub struct Placement { pub pts: Hns, pub silence: u32, pub skip: u32, pub restart: bool }
#[derive(Clone, Debug)]
pub struct SampleTimeline { rate: u32, anchor: Option<(u64, Hns)>, next: u64 }
impl SampleTimeline {
  pub const TOLERANCE: Hns = Hns::from_millis(20);
  pub const MAX_FILL: Hns = Hns::from_secs(1);
  pub fn new(sample_rate: u32) -> Self;
  pub fn place(&mut self, qpc: Hns, frames: u32) -> Placement;
  pub fn expected(&self) -> Option<Hns>; // time of `next`, None before the first buffer
}
```
   Document each field. `pts` is the raw QPC-timeline PTS of the first emitted frame (silence if there is any, otherwise audio). `silence` is the number of zero frames to emit first. `skip` is the number of frames to drop from the buffer's start. `restart` means 'drain the encoder first'. Doc TOLERANCE as a calibration knob: corrections stay below the lip-sync detection threshold of about 45 ms (ITU-R BT.1359).
2. Private helpers, using i128 so nothing overflows:
   - `time_of(n) = anchor_time + Hns(((n - anchor_n) * 10_000_000 / rate))`;
   - `frames_in(d: Hns) -> u32 = d.ticks() * rate / 10_000_000`.
   Use `i128::from`, and `try_from(..).unwrap_or(MAX)` instead of `as` casts.
3. `place(qpc, frames)`:
   - No anchor yet: anchor at `(next, qpc)`, `next += frames`, return `{pts: qpc, silence:0, skip:0, restart:true}`.
   - Otherwise compute `expected = time_of(next)` and `err = qpc - expected`.
   - `err > MAX_FILL`: re-anchor at `(next, qpc)`, `next += frames`, return `restart:true` with `pts: qpc`.
   - `err > TOLERANCE`: `s = frames_in(err)`, `next += s + frames`, return `{pts: expected, silence: s}`.
   - `err < -TOLERANCE`: `k = frames_in(-err).min(frames)`, `next += frames - k`, return `{pts: expected, skip: k}`.
   - Otherwise: `next += frames`, return `{pts: expected}`.
4. Tests in the same module (normal `#[test]`, not ignored):
   - `sample_timeline_first_buffer_restarts`;
   - `sample_timeline_is_sample_exact_when_on_time`: 48 kHz, 1,000 buffers of 480 frames at qpc = t0 + k*100_000, no corrections, and pts equals the exact value every time;
   - `sample_timeline_ignores_jitter_within_tolerance`: ±5 ms noise;
   - `sample_timeline_fills_a_gap_with_silence`: 50 ms late gives silence == 2400;
   - `sample_timeline_drops_frames_when_the_device_runs_fast`: 30 ms early gives skip == 1440;
   - `sample_timeline_restarts_after_a_long_gap`: 5 s late gives restart with pts == qpc;
   - `sample_timeline_bounds_drift_over_30_minutes`: simulate a device at ±100 ppm with 180_000 buffers of 480 frames, where the true QPC per buffer is 100_000 * (1 ± 1e-4). After each place, assert `|pts + dur(silence) - qpc_of_first_kept_frame| <= TOLERANCE + 1 ms`.
5. Docs: add one paragraph to DESIGN §6 'Master clock and PTS' (device clock vs QPC drift and how SampleTimeline corrects it), and one line to the 'Time' section in ARCHITECTURE.md. In ROADMAP Phase 2, add the sub-item '- [x] `SampleTimeline` (audio clock drift)'.
